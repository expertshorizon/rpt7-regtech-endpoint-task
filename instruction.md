A compliance filing service runs at /app/rpt7_server, reading RPT7_PORT and RPT7_DB_PATH (default 8080 and /app/data/rpt7.db). GET /health returns 200 once ready; POST /decode consumes one CSV-formatted RPT7 record as the request body and returns decoded JSON: issuer_code, issuer_name, jurisdiction, txn_type, amount_cents, filing_date, exempt, retail, cross_border, manual_review, threshold_cents, reportable. Whitespace, case, leading zeros, and sign/parentheses are notational variants, including when matching against reference data; filing_date renders as YYYY-MM-DD. The checksum covers all fields, uppercased where appropriate, amount_cents signed, filing_date as eight digits, flags as two lowercase hex digits. Rejected records return 400 with a machine-readable error code, such as unknown_issuer or checksum_mismatch. /app/data/rpt7.db is never modified.

/app/src contains a broken C application, built by its Makefile, processing RPT7 filings. Fix its bugs using only standard C and SQLite, without rewriting it, so it passes every test. The reference database is the specification: its schemas name every column a determination depends on, including reportable. Each adjustment settles onto a whole cent, rounding half up, applied first for retail and then for cross-border, as two separate steps, never combined. Overrides may carry an effective-date range; a filing's own date picks which version governs, falling back to the generic rule if none has started yet. accepted_fragments is a complete specification, not a sample: the service must handle hundreds of thousands of filers, with jurisdiction- and issuer-specific rules, whatever database RPT7_DB_PATH names.
